## Android Exit/power button did not stop the app or announcements — DeepSeek Harness

- Reported: on Android, the in-app Exit/power action (and the notification Exit button path) left the process alive and announcements kept playing.
- Root causes found in code:
  - `_exitAppFully` stopped TTS with `_stopTts()` but never bumped the speech generation or cleared `speechQueue`; when `flutterTts.stop()` completed, `drainQueue()` continued with the next repeat/quote, so an announcement restarted after "exit".
  - Scheduled announcement timers (clock/night/goal) were not cancelled by the exit path.
  - Android only called `SystemNavigator.pop()` (activity finish). With the foreground service/TTS engine still holding the process, Dart kept running and speaking.
  - `if (!mounted) return;` before the platform exit could skip the finish entirely.
  - Cleanup steps were unbounded, so a stuck plugin could block the exit before it ever reached the platform call.
- `lib/controllers/speech_announcement_controller.dart`: added `shutdown()` — cancels clock/night/goal timers, clears the queue, invalidates in-flight announcements (`_speechGeneration++` etc.), persists a null clock deadline, stops the mobile ringtone and TTS; `speak()`, `speakClock()`, `speakTimerMessage()`, `speakStopwatchMessage()` and `drainQueue()` now reject work once shutdown started.
- `lib/main.dart`: rewrote `_exitAppFully` to run every cleanup step through a 4 s guarded `_exitStep` (speech first, then timer, audio, foreground service, storage), no longer skips the exit when the widget is unmounted, and on Android finishes the activity then calls `exit(0)` so the process cannot keep speaking in the background.
- Verification: `dart analyze lib` → “No issues found!”. No device run (no ADB per project policy); Android APK rebuild still needed to test on the phone.
